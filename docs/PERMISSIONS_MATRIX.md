# Permissions Matrix

The single source of truth is
[`apps/healthcare_erp/healthcare_erp/setup/roles.py`](../apps/healthcare_erp/healthcare_erp/setup/roles.py)
— this document is a human-readable rendering of it, regenerated by hand whenever that file
changes. `sync_doctype_permissions()` applies it idempotently on every install and migrate, so
the Desk's Role Permission Manager is never the source of truth for this app's roles.

**Administrator / System Manager** aren't listed below — Frappe grants System Manager
unrestricted access to every doctype by default, and it's reserved for IT/superuser
administration, never given to clinical or business staff.

**Record-level scoping for `Patient`**: a patient can only ever see their *own* records. This
isn't a role permission — it's a `User Permission` (`Allow: Patient`, `Apply to all DocTypes`)
created automatically the moment a `Patient` record is linked to a `User`
(`healthcare_erp/healthcare_erp/doc_events/patient.py`). The table below is just the
doctype-level ceiling that User Permission narrows down to one record.

## Adding a new role or doctype grant

1. Add/extend an entry in `ROLE_PERMISSION_MATRIX` in `roles.py` using the `READ` /
   `READ_CREATE` / `CRUD` / `CLINICAL` / `FULL` shorthands (or a custom dict) at the top of
   that file.
2. Run `bench --site <site> migrate` (calls `after_migrate` → `sync_doctype_permissions()`),
   or call it directly: `bench --site <site> execute healthcare_erp.setup.roles.sync_doctype_permissions`.
3. Update this file's table to match.
